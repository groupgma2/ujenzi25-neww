# UJENZI 25 — COMPLETE SYSTEM OPERATION WORKFLOW

## IMPORTANT INSTRUCTION

Ujenzi 25 must NOT be developed as a collection of independent web pages.

The system must operate as a connected **digital platform / operating system** where users perform real actions, requests move through workflows, different parties interact, data changes status, and each dashboard provides tools based on the user's role.

The UI pages are only the interface. The real system must operate through:

* User actions
* Workflows
* Status changes
* Requests
* Orders
* Bookings
* Communication
* Notifications
* File sharing
* Payments
* Reviews
* Role-based permissions

---

# 1. THE THREE MAIN PARTIES

The system has three main parties:

## A. CLIENT / CUSTOMER

The client can:

* Request consultation
* Order construction materials
* Post labour jobs
* Search properties
* Enquire about properties
* Search rental houses
* Contact landlords
* Book hotels or apartments
* Upload documents
* Send messages
* Receive notifications
* Make payments
* Track requests
* Download delivered files
* Leave reviews

---

## B. UJENZI 25 COMPANY / ADMINISTRATION

Ujenzi 25 is the central operating party of the platform.

Depending on the service, Ujenzi 25 acts as:

* Consultant
* Administrator
* Manager
* Coordinator
* Trusted middleman
* Quality controller
* Listing verifier
* Payment and invoice manager
* Dispute handler
* Labour service provider

The Company must have visibility and control over operations that require management, verification, mediation, or approval.

---

## C. THIRD-PARTY PARTNERS

Third-party partners include:

* Material suppliers
* Labour teams
* Contractors
* Property sellers
* Landlords
* Hotel owners
* Apartment owners

Partners must have their own workspace/dashboard where they manage their services, listings, requests, and transactions.

The general system operation is:

USER
↓
SELECTS A SERVICE
↓
CREATES A REQUEST / ORDER / LISTING / BOOKING
↓
SYSTEM VALIDATES THE ACTION
↓
CORRECT PARTY IS NOTIFIED
↓
PARTIES COMMUNICATE
↓
REQUEST MOVES THROUGH WORKFLOW STATES
↓
FILES / INFORMATION ARE SHARED
↓
PAYMENT OR APPROVAL WHEN REQUIRED
↓
SERVICE IS PERFORMED
↓
STATUS IS UPDATED
↓
CLIENT TRACKS PROGRESS
↓
SERVICE IS COMPLETED
↓
REVIEW / RECORD / HISTORY IS SAVED

Every important operation must be persistent in the database.

# DEVELOPMENT REQUIREMENT FOR THE AGENT

From now on, do not develop Ujenzi 25 as a normal website containing only pages.

Develop it as a connected business platform.

Every new feature must answer:

1. Who performs this action?
2. Which party receives the action?
3. What database record is created?
4. What status does the operation start with?
5. Who is notified?
6. Who can view the operation?
7. Who can change the status?
8. What happens after approval?
9. Is messaging required?
10. Are files required?
11. Is payment required?
12. How does the operation complete?
13. Where is the history stored?
14. Which dashboard manages this operation?

DO NOT build disconnected UI pages.

DO NOT create fake workflow actions.

DO NOT create dashboard cards without real operations behind them.

Every page must connect to a real system function.

Every important action must persist in the database.

Every business operation must have a clear workflow from creation to completion.

UJENZI 25 MUST OPERATE AS A CONNECTED DIGITAL BUSINESS PLATFORM, NOT JUST A WEBSITE.
